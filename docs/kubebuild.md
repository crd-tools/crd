# Схемы из kubebuilder-маркеров

Как подключить схему типа, описанного маркерами `// +kubebuilder:...`: своего
legacy-пакета, `k8s.io/api` или стороннего модуля. Читайте, когда в вашем типе
есть поле чужого типа, которому не добавить `CRD()` или `Rule()`.

## Зачем

Маркеры — это комментарии. После компиляции они исчезают, и схему такого типа из
программы уже не получить. Поэтому схемы таких типов заранее собираются через
[controller-tools](https://github.com/kubernetes-sigs/controller-tools) в снимки,
снимки встраиваются в проект через `go:embed`, а пакет читает их в рантайме.

Маркеры в своих новых типах писать не нужно: новое описывается правилами
([rules.md](rules.md)).

## Пример

```go
type Spec struct {
	Resources   legacy.Resources    `json:"resources" crd:"kubebuild"`
	Tolerations []corev1.Toleration `json:"tolerations" crd:"kubebuild"`
}
```

```go
import "example.com/project/internal/schemas"

func init() {
	crd.SetDERSource(schemas.FS())
}
```

Дальше поля с меткой получают схему из снимков в `SchemaFor` и при сборке CRD.

## Метка

По умолчанию `crd:"kubebuild"`. Значение может стоять в списке через запятую:
`crd:"other,kubebuild"`. Сменить метку — `crd.SetKubebuildTag`.

Тип поля разворачивается до именованного типа: `T`, `*T`, `[]T`, `[N]T`,
`map[K]T`. Подходят типы из других пакетов и из того же пакета. Не подходят
встроенные типы (`int`, `string`), дженерики, анонимные структуры и интерфейсы.

Снимки собираются с замыканием: типы, на которые ссылается помеченный тип, тоже
попадают в снимки.

Под меткой поддерево берётся из снимка как есть, кроме типов, у которых есть
`CRD()`, `Rule()` или `RegisterSchema`: схема из кода важнее снимка
([schema-sources.md](schema-sources.md)).

## Чужой CRD целиком

Чтобы подключить чужой ресурс целиком (например, `HTTPRoute` из Gateway API),
встройте его тип в обёртку с меткой:

```go
type HTTPRoute struct {
	gwv1.HTTPRoute `json:",inline" crd:"kubebuild"`
}

var HTTPRouteResource = crd.New[HTTPRoute]().
	Group("gateway.networking.k8s.io").Kind("HTTPRoute").Plural("httproutes").
	Version("v1", true, true, crd.Status())

func init() {
	crd.Add(HTTPRouteResource)
}
```

Встроенное поле с меткой не разворачивается по Go-полям: его схема берётся из
снимка и вливается в объект вместе с описанием типа. В `crd.OpenAPI` встроенный
тип остаётся отдельным компонентом и подключается через `allOf`. Обёртка — только
носитель схемы; в коде приложения пользуйтесь исходным типом.

CRD в группах на `k8s.io` и `kubernetes.io` должен нести аннотацию
`api-approved.kubernetes.io` со ссылкой на одобренный PR, иначе API-сервер его не
примет. Берите значение из официальных CRD проекта:
`.Annotation("api-approved.kubernetes.io", "https://github.com/...")`.
`validation.Validate` сообщит, если её нет.

Если проект описывает часть схемы своими тегами в комментариях, их применяют
модификаторы (см. ниже). Для Gateway API есть готовые: с ними CRD Gateway API
v1.6.2 совпадают с официальными CRD обоих каналов полностью — пути свойств,
ограничения и описания.

## Модификаторы

Некоторые проекты описывают часть схемы не маркерами kubebuilder, а своими тегами в
комментариях. controller-tools их не понимает и оставляет в описаниях. Такие теги
применяет модификатор — функция, которая правит схему каждого типа ресурса при
сборке.

Gateway API так задаёт каналы. Канал — это набор правок поверх одной и той же
схемы: `standard` удаляет экспериментальные поля и применяет свои проверки,
`experimental` оставляет все поля и применяет свои. В кластер ставится CRD одного
канала, и схема для него должна быть того же канала.

```go
import "crd.tools/crd/modifiers/gatewayapi"

var HTTPRouteResource = crd.New[HTTPRoute]().
	Group("gateway.networking.k8s.io").Kind("HTTPRoute").Plural("httproutes").
	Version("v1", true, true, crd.Status()).
	Modifiers(gatewayapi.Standard())
```

- **Модификаторы принадлежат определению.** Их видят `Build`, `Encode` и
  `crd.OpenAPI` этого определения; `SchemaFor` и другие определения — нет.
- **Каждая сборка независима.** Модификаторы применяются к копиям схем, общий кеш
  не меняется. Можно собрать CRD, поменять набор и собрать снова:

  ```go
  HTTPRouteResource.Modifiers(gatewayapi.Standard())
  standard, _ := HTTPRouteResource.Build()

  HTTPRouteResource.Modifiers(gatewayapi.Experimental())
  experimental, _ := HTTPRouteResource.Build()
  ```

- **`Modifiers` заменяет набор целиком**, без аргументов — очищает.
- **Модификатор получает схему одного типа** со ссылками `$ref`, до их раскрытия:
  так результат одинаков в манифестах и в компонентах OpenAPI.
- **В `crd.OpenAPI`** компоненты строятся для каждого определения с его
  модификаторами. Если общий тип у двух определений получился разным (разные
  наборы), это ошибка: у компонента может быть только одна схема.
- **Снимки не меняются:** они хранят схемы с исходными тегами, и из одного снимка
  получается любой канал.

Своё преобразование — любая реализация `crd.Modifier`:

```go
.Modifiers(crd.ModifierFunc(func(key string, s *apiextv1.JSONSchemaProps) error {
	...
	return nil
}))
```

## Пакет со снимками

```
internal/schemas/
    zz_generated.crd.go             # go:embed каталога data и функция FS()
    data/
        index.der                   # корни, места меток, таблица тип → файл
        example.com~legacy~v1.der   # снимки типов одного пакета
        k8s.io~api~core~v1.der
```

Go-файл не импортирует ничего, кроме стандартной библиотеки. Каталог `data` —
артефакт, его стоит коммитить.

Снимки читаются лениво: при первом запросе схемы, по одному файлу на пакет.
Порядок `init` между пакетами не важен.

## Формат файлов

ASN.1 DER (`encoding/asn1`) с детерминированной кодировкой: одинаковые исходники
дают одинаковые байты. Первое поле каждого файла — версия формата, она читается
отдельно, поэтому снимки другой версии распознаются. Схема каждого типа —
`JSONSchemaProps` в protobuf-кодировке Kubernetes. Ссылки между типами — `$ref`
с ключом `путь/пакета.Тип`. Индекс содержит таблицу «тип → файл + хэш схемы»:
по ней реестр находит нужный файл и проверяет конфликты, не читая сами файлы.

Формат реализован в пакете `crd.tools/crd/registry`.
